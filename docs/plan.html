英文垂直站群：
从采集搬运到可控内容工厂

你要的是 8 个能收录、有流量、能变现的英文站，用二级域名串起来，DeepSeek 做内容生产。 技术上这件事完全可行——但「采集完整内容再改写」这个做法本身，是整条链路上唯一会让你归零的环节。 这份文档给出替代路线：同样的自动化、同样的低成本，但内容来源和加工方式换成算法和广告主都认可的形态。

技术栈 Windows · 宝塔 · Apache · WordPress 规模 8 个二级域名站点 日产能 16–24 篇 单篇成本 ¥0.03 左右

先说要改的那件事

不是道德说教，是投入产出比。下面三条决定了你两年后是在收钱还是在重开。

01 / 政策

搬运 + 洗稿已经是明确的封禁项

Google 的 scaled content abuse 政策把「批量生成对用户无增量价值的页面」定义为 spam， 2024 年 3 月核心更新后由系统自动判定，不再依赖人工。整站搬运是这条政策最典型的命中样本。

02 / 变现

AdSense 审核这一步就过不去

采集站的特征（无作者、无原创、内容重复）在审核环节会被直接拒。即使侥幸过审， 后续的无效流量检测和版权投诉也会让账户先于收益被停掉。

03 / 成本

但 AI 原创的成本结构确实变了

DeepSeek 生成一篇 1500 词结构化长文约 $0.004。人工写手同规格 $50–150。 这个 1000 倍的差距，才是站群第一次真正跑得通的原因。

结论

把内容来源从「别人的文章」换成「公有领域资料 + 开放数据集 + 模型自身知识」， 把加工方式从「同义词替换」换成「重组结构 + 补充可核对的具体数值 + 生成对比表格」。 流水线一行代码都不用改，只是换掉 prompt 和素材源。

站群拓扑

二级域名共享主域权重，这是它相对独立新域名的最大优势。代价是所有子站在 Google 眼里同属一个实体， 所以隔离要做在「安装层」而不是「域名层」。

为什么用「独立安装」而不是 WordPress Multisite

Multisite 省事，但它把所有子站绑成一个实体：共享用户表、共享插件、共享一份「站点质量」评估。 一旦某个子站因为内容问题被人工处罚，整张网络的表现会一起下滑。独立安装意味着 风险隔离——最坏情况是一个站归零，其余七个照常跑。这是站群能活过两年的结构前提。

内容引擎

这是已经写好的流水线，五个环节，每一步都有明确的失败处理。跑批命令就是 run.py gen --count 3。

STEP 01
选题

模型按站点定位产出 4–9 词长尾词，标注搜索意图和优先级，写入 SQLite 队列。

STEP 02
素材

只轮询配置里列出的源，先查 robots.txt，再按 license 字段决定能用多少。公有领域优先。

STEP 03
写作

System prompt 锁死：禁止连续 10 词重合、禁止编造数据、必须含比较表格和 4–6 条 FAQ。

STEP 04
质检

标题归一化去重、slug 冲突检测、正文 SimHash 指纹比对（汉明距离 ≤3 判重）。

STEP 05
发布

WordPress REST API 推草稿，自动建分类标签，末尾注入 JSON-LD 结构化数据。

Prompt 里真正起作用的三条约束

绝大多数 AI 内容站失败，不是因为模型写得差，而是因为没人告诉它不要做什么。 这三条是实测下来对「像人写的」贡献最大的：

  • 禁止宽泛表述。「工具价格差异很大」不合格，「PEX 压接钳 $35–60，比铜管焊接省 2 小时」合格。要求模型每 200 词至少给一个具体数字。
  • 禁止结构套路。不允许「总而言之」「在当今快节奏的世界里」这类开头，禁止用反问句开篇。正文必须有一个「最容易犯的错」小节。
  • 禁止虚构。不引用不存在的研究、不编造价格、不伪造专家身份。无法确证的数字宁可写区间。
成本核算

DeepSeek V3 输出 $1.10 / 百万 token，输入 $0.27 / 百万 token。 一篇 1500 词文章的往返约 4000 输入 + 3000 输出，成本 $0.0044，折合人民币约 3 分钱。 8 个站每天 24 篇，月成本约 $3–5；算上重试和加长版本，实际按 $15–30 / 月做预算足够宽裕。

收录加速

新站的收录速度取决于三件事：抓取预算、站点可信度、内链可达性。按下面顺序做，比盲目堆量有效得多。

第一阶段：建站后 0–7 天，先别急着发文章

  • 每个子站装好 WordPress，固定链接设为 /%postname%/，关闭评论（避免垃圾评论拖累质量评分）
  • 建四个必备页面：About（写清楚谁在运营、编辑原则）、Contact（真实可达邮箱）、Privacy Policy、Editorial Policy
  • Google Search Console 逐站添加，提交 sitemap；Bing Webmaster 同步添加
  • 把 <INDEXNOW_KEY>.txt 上传到每个站根目录，IndexNow 能让 Bing 在几分钟内抓取
  • 站点地图用 WordPress 自带的 /wp-sitemap.xml 即可，不必装重型 SEO 插件

第二阶段：8–30 天，只发精品

  • 每站先发 12–15 篇，全部人工过一遍再发布。这个阶段的目标不是量，是让 Google 建立「这个站的内容值得抓」的判断
  • 每篇至少 3 个内链，优先链向已收录的页面，形成抓取闭环
  • 首页放「最新文章」和「热门分类」两个区块，给爬虫一个稳定入口
  • 分类页要能索引，且每个分类下至少有 3 篇文章，否则先设为 noindex
  • 观察 Search Console 的「已发现但未编入索引」数量，如果持续堆积，说明是内容质量而不是抓取问题

第三阶段：31–90 天，开始放量

  • 每天每站 2–3 篇，保持稳定节奏。不要一天发 50 篇，突发量是明显的机器特征
  • 每篇发布后立即 IndexNow 提交，Bing/Yandex 侧基本当天收录
  • Google 侧靠内链和 sitemap 的自然更新，不要用任何「快速收录」服务
  • 开始做数据型页面：成本对比表、规格数据库、季节日历——这类页面被引用率高，是最快带来自然外链的资产
  • 每周检查一次索引率（已编入索引 / 已提交），低于 60% 就停下来查质量，别继续加量
一个必须知道的事实

Google 在 2023 年就关闭了 sitemap ping 接口，所谓的「Google 快速收录 API」只对招聘信息和直播开放， 对普通文章无效。市面上卖「24 小时收录」的服务，要么用的是 IndexNow（只对 Bing 有效）， 要么是给你刷垃圾外链——后者会让站点在下一个算法更新里直接消失。

不建议做的事

买外链、用 PBN 互链服务、批量提交目录站、买「老域名带权重」。这四件事在 2025 年的风险收益比已经彻底反转： 过去能带来 20% 提升，现在是一次算法更新归零的概率问题。自然外链只能靠数据型页面换。

90 天执行时间线

DAY 01 – 07

地基

主域解析泛二级域名，Apache 配 mod_vhost_alias，8 个独立 WordPress 装好。 申请通配符 SSL（必须走 DNS-01 验证）。每站生成 Application Password 填入 .env。 跑 python run.py check 确认 8 个站全部返回 200。

DAY 08 – 21

内容校准

先只做 diy 一个站。跑 gen --count 10，全部转成 draft，逐篇读。 按实际产出调整 niche / audience / tone 三个字段—— 这三个字段的颗粒度直接决定文章像不像内行写的。校准到「读起来不需要大改」再推广到其余七站。

DAY 22 – 45

首批上线

每站 12–15 篇精品，人工过审后发布。提交 Search Console 和 Bing，上传 IndexNow 密钥文件。 这个阶段不追求量，目标是拿到第一批索引。同步开始申请 Amazon Associates（有成交记录后再申请更容易过）。

DAY 46 – 75

稳定放量

每天每站 2–3 篇，接到 Windows 任务计划程序自动跑。每周看一次索引率， 低于 60% 就停下来排查而不是继续加量。开始做数据型页面：成本对比表、规格数据库、季节日历。

DAY 76 – 90

变现接入

流量起来后接 Ezoic（无门槛），同时申请 AdSense。两个都过就只留 RPM 高的那个。 检查每个站的联盟链接点击率，淘汰零点击的推荐位——推荐位数量不是越多越好。

一句话总结

技术方案已经全部写好并跑通，成本低到可以忽略。真正决定成败的是内容里有没有 别处找不到的具体信息。AI 能解决「写出来」，解决不了「凭什么信你」—— 后者靠的是每个站里那些愿意花两小时核对一个数字的部分。
